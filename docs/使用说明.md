# trellis-plus v2.1 使用说明

## 1. 前置条件

- 项目已 `trellis init`（Trellis 0.6.17，OpenCode 平台），且是 git 仓库。
- Node ≥ 18、python3、git。
- 可选：`ocr`（alibaba/open-code-review）。没有或不可用时自动降级为委托模式。
- 单测门禁需要 Maven（Java 8 + JUnit5 + Mockito）。
- `/grill-me`、`grilling` 技能由你自己装在 OpenCode 里（缺失只告警）。

## 2. 安装与维护

```bash
node trellis-plus.mjs apply  <项目目录> --dry-run   # 先看会改什么
node trellis-plus.mjs apply  <项目目录> --all       # 硬门禁 + plugin 补丁 + agent 补丁 + git hook
node trellis-plus.mjs doctor <项目目录> [--fix]     # 每次 `trellis update` 之后跑一次
node trellis-plus.mjs revert <项目目录> [--purge]   # 还原补丁；--purge 同时删除随包文件
```

- `apply` 幂等；`plus.config.json` 属于项目，不会被覆盖。
- 安装后把 `.trellis/plus/` 与 `.opencode/` 的新增文件提交进仓库，队友直接用 `node .trellis/plus/gate.mjs …`。
- `doctor` 会提示非法的 `profile` / `gates` 配置，以及不是 `error` 的开关。

## 3. 日常流程

以下 `GATE` = `node ./.trellis/plus/gate.mjs`，`<T>` = 任务目录。

1. **创建任务并定级（AI 建议 → 用户选择）**：AI 先看代码（几个 Service/Controller、几个模块、有无库表/契约/事务变更），给出 S/M/L 建议与理由，在对话里请你选择；选定后执行 `GATE tier <T> S|M|L --reason "<理由；用户选 X>"`（S/M 必须写原因）。再 `GATE seed <T>` 生成模板。
2. **勘探（仅 L）**：用 trellis-research 写 `research/code-map.md`（锚点格式 `文件:行#符号`）。
3. **澄清**：在 OpenCode 里手动输入 `/grill-me`，结论写进 `prd.md` 的“决策记录”，需求按功能分 `###` 小节、每条编号 `R<n>`，把“对齐状态”改为“已对齐”，待确认问题清零。运行 `GATE align <T>`。
4. **起草（M/L，建议新会话）**：加载 `plus-draft` 技能写 `design.md`、`implement.md`；运行 `GATE lint-plan <T>`，按提示修到通过。
5. **评审（仅 L，新会话）**：派发 `plus-design-reviewer`（最多 2 轮），在 `reviews/design-review-resolution.md` 逐条回应阻塞项（`- #3 采纳 — …` 或 `- #4 驳回 — <path:行 或 prd.md 出处>`），运行 `GATE design-review <T>`。需人工确认项 ≥ 3 时可用 `/plus-grill-design`。
6. **开始实现**：`task.py start` 会再次运行该级别的全部计划类门禁。
7. **实现与检查**：implement / check 子 agent 只做静态单测检查。
8. **单测门禁（2.4）**：`GATE test --task <T> --run`，每个被改的 Service/Controller 要有同模块、本次改过、含 `@Test` 的单测；`--run` 按模块执行 Maven。
9. **OCR（2.5）**：`GATE ocr --task <T> --run`。
   - 先 `ocr llm test`；可用则调用 ocr，报告保存为 `reviews/ocr-r<N>.json`。
   - 不可用则打印 **委托模式** 指引：由 agent 自己审查代码，写出同格式报告。
   - 把每条 finding 分诊写入 `reviews/ocr-triage.md`（`- [fixed|false-positive|deferred] 文件:行 — 说明`）。critical/high 不能 deferred，误报要引用存在的 `path:行`。同文件同行的多条 finding 要各写一行。
   - 只有上一轮含 critical/high 且已修复时才可重跑，最多 2 次（`--force` 越过，并告知用户）。
   - 校验：`GATE ocr --task <T>`。
10. **提交前**：`GATE pre-commit --task <T>`（静态）；`git commit` 时 hook 再查一遍已暂存文件。

随时可用（0 token）：`GATE status <T>` 看下一步；`GATE usage <T> --phase <名> --tokens <n>` 记 token；`GATE matrix <T>` 打印 R→模块→测试矩阵；`GATE anchors <T>` 单独核对锚点；`GATE gates` 看开关。

## 4. 文档模板要点

- **prd.md**：`对齐状态：已对齐|未对齐`；“需求与验收”下按功能 `### 名称`，每节一张表（编号 R1…、需求、验收标准）；决策记录表 `D<n>`（问题/结论/来源/影响）；待确认问题为空写“无”。
- **design.md**（M 可省第 2、9 节）：0 评审导读、1 背景与目标、2 术语、3 整体方案、4 模块拆分、**5 数据库变更**（表/变更类型/内容/兼容与回滚/对应R，或 `无变更：原因`）、**6 详细设计**（接口表、关键逻辑伪代码树、只写改动字段的字段与口径）、7 异常与边界、8 影响分析（引用数写“命令 → 命中数”，≥5 处须标“高风险”）、9 非功能、10 依赖/风险/回滚、11 覆盖矩阵与上线检查、12 开放问题。
- **implement.md**：`### 步骤 n：类名` 下只写“文件”（反引号路径，新增文件写“新增”）和“改什么”；测试矩阵（对应R/类/用例/类型，类型只写 正常/边界/异常）；测试豁免（无则写“无”）。
- 体积上限：prd 10 KB、design M 12 KB / L 30 KB、implement 20 KB、三者合计 60 KB；超了拆成父子任务。

## 5. 配置 `.trellis/plus/plus.config.json`

只写要覆盖的键：

```json
{
  "profile": "standard",
  "gates": { "designReview": "warn" },
  "ocr": { "mode": "auto", "maxRerun": 2 },
  "testGate": { "methodLevel": "warn" },
  "hook": { "runTests": false }
}
```

| 键 | 说明 |
|---|---|
| `profile` | `standard`（默认）/ `strict`（另将 ocr.onIncomplete、methodLevel 提到 error）/ `light` |
| `gates.<名>` | `align lintPlan designReview manifests test ocr hook` → `error` / `warn` / `off` |
| `ocr.mode` | `auto`（先 `ocr llm test`，失败转委托模式）/ `cli`（仅 ocr，失败即错误）/ `delegate`（不调用 ocr） |
| `ocr.maxRerun` | 默认 2（首次不计） |
| `testGate.methodLevel` | 方法名近似检查：`warn`（默认）/ `error` / `off` |
| `testGate.runCommand` | 默认 `mvn -q -pl {module} -am test -Dtest={classes} -Dsurefire.failIfNoSpecifiedTests=false` |
| `limits.*`、`tiers.maxClassesM` | 体积上限、M 级最多几个类 |

## 6. 退出码、任务选择与绕过

- 退出码：0 通过 / 1 门禁失败 / 2 用法或配置错误。
- 任务选择（hook、OCR）：`--task` > `TRELLIS_PLUS_TASK` > 会话任务 > **唯一**的 in_progress 任务（`00-bootstrap-*` 不计）；有多个且没有指定时不猜：hook 里 OCR 降为告警，命令行报错。
- 绕过（谨慎，并告知用户）：`TRELLIS_PLUS_SKIP_GATE=1 git commit …` 或 `git commit --no-verify`。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| `task has no tier` | AI 先给建议与理由，你选定后再 `GATE tier <T> S|M|L --reason "…"` |
| `tier S refused / tier S is not allowed` | S 不能改 Service/Controller，改用 M 或 L |
| lint-plan 报占位符 | 把 `【填写：…】` 全部替换掉（包括伪代码块与表格里的） |
| lint-plan 报锚点失败 | 核对 `文件:行#符号` 是否真实存在（符号需在 ±15 行内） |
| OCR 提示 `DELEGATION MODE` | `ocr llm test` 失败或没装 ocr：按提示由 agent 自审并写 `ocr-r<N>.json` |
| OCR 报 `finding not triaged` | 每条 finding 需要一行分诊；同文件同行有两条就写两行 |
| OCR 报 `status partial` | 有文件没被审到：重跑或自己审那些文件 |
| `trellis update` 之后补丁丢了 | `node trellis-plus.mjs doctor <项目> --fix` |
| 配置写错后所有 gate 命令退出 2 | 看报错的键名，改 `plus.config.json`；`doctor` 也会提示 |
