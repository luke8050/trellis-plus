# trellis-plus v2.1 方案介绍

> 适用：已 `trellis init`（Trellis 0.6.17，OpenCode 平台）的 Java 8 + Maven 多模块 + JUnit5 + Mockito 项目。
> 本文说明“为什么这样做、做了什么、验证到什么程度”。怎么用见《使用说明.md》。

## 1. 要解决的问题

| 目标 | 做法 |
|---|---|
| 降 token | 规划文档与每轮面包屑变小；只有 L 级走完整流程；门禁命令不耗 token |
| 提质量 | 与用户的澄清记录进 `prd.md`；设计文档能被人在约 20 分钟内评审；一个独立评审员；代码锚点必须真实 |
| 保障 | 每个被改的 Java Service/Controller 必须有同模块、本次改过、含 `@Test` 的单测；OCR 严重级别分诊；git pre-commit hook 兜底 |

总体原则是**做减法**：删掉 alignment 门禁、三个 reviewer、REQ/DES/IMP/TEST 的 ID 链和 hash 绑定；保留已验证的 hook、agent 补丁、单测门禁、OCR 分诊。

## 2. 总体结构

一个零依赖 Node 脚本（Node ≥ 18）：

- `trellis-plus.mjs`：安装器（`apply` / `doctor` / `revert`），把门禁与补丁装进项目。
- `.trellis/plus/gate.mjs`：门禁脚本，随项目提交，队友无需安装本工具。
- 对 Trellis 原有文件打补丁：`workflow.md`、`task.py`（`start` 前硬门禁）、`trellis-context.js`、两个原生 agent、`.git/hooks/pre-commit`。

### 分级（AI 建议 + 用户选择，存 `task.json` 的 `meta.plus_tier`）

| 级别 | 适用 | 规划产物 | 门禁 |
|---|---|---|---|
| S | 文档、注释、配置文案、纯测试、不改行为的重命名；**不得改 Service/Controller** | prd.md | align · 单测 · hook |
| M | ≤ 3 个 Service/Controller、同一 Maven 模块、不涉及库表/对外契约/事务并发 | prd + design + implement | + lint-plan |
| L | 其余 | + research/code-map.md + 独立设计评审 | 全部 |

### 流程

```
Phase 1  1.0 创建 + 定级（AI 建议理由 → 用户选 → gate tier --reason）→ [L] 1.2 勘探 → 1.1 澄清（建议 /grill-me，没装可跳过）并记入决策记录，gate align
         → [新会话] 1.6 起草 design/implement，gate lint-plan → [L，新会话] 1.7 评审(≤2 轮)，gate design-review
         → 1.3 配置上下文 → 1.4 task.py start（硬门禁复查）
Phase 2  2.1 实现 → 2.2 check → 2.4 单测门禁(正式 --run 只此一次) → 2.5 OCR（critical/high 修复后才重跑，最多 2 次）
Phase 3  gate pre-commit → 提交（git hook 再查一遍已暂存文件）
```

## 3. 硬性门禁与开关

每个门禁都能设为 `error`（阻断，默认）/ `warn`（只告警）/ `off`（不运行）。`profile`（standard 默认 / strict / light）给一组预设，`gates.<名称>` 单项覆盖；`gate gates` 打印生效值。

| 开关 | 检查什么 | strict | standard | light |
|---|---|---|---|---|
| align | prd：已对齐、待确认清零、决策记录(M/L)、R<n> 编号、占位符、体积 | error | error | error |
| lintPlan | design/implement 真实性（锚点、章节、R 覆盖、影响分析、测试矩阵）、体积、M 级限制 | error | error | warn |
| designReview | L：评审报告头与表格一致、每个阻塞有回应 | error | warn | off |
| manifests | `start` 前 implement/check.jsonl 有真实 spec 条目 | error | off | off |
| test | 被改 Service/Controller 有同模块、本次改过、含 @Test 的单测；S/M 限制 | error | error | error |
| ocr | OCR 报告存在、未过期、每条 finding 已分诊 | error | error | warn |
| hook | 整个 git pre-commit hook | error | error | error |

始终开启、不可关：`start` 前必须已定级；退出码约定（0 通过 / 1 门禁失败 / 2 用法或配置错误）；`TRELLIS_PLUS_SKIP_GATE=1` 是唯一的整体绕过。

## 4. 本轮（v2 → v2.1）变更

| 项 | 变更 |
|---|---|
| prd 模板 | “需求与验收”按功能分 `### 功能名` 小节，每节一张需求表（`R<n>` 全文唯一）。门禁改为读取所有表；无分组/空分组只告警 |
| design 模板 | 新增独立章节 **5 数据库变更**（M/L 必填，无变更写“无变更：原因”）；**6 详细设计**去掉“数据结构”“主流程”，关键逻辑改用树形伪代码，字段与口径只写本次改动的字段；后续章节顺延为 7 异常与边界 … 12 开放问题 |
| implement 模板 | 精简为：文件 / 改什么 + 测试矩阵 + 测试豁免。去掉单测描述、验证命令、回滚点、手工验证清单、提交前验证 |
| workflow | Phase 1 流程按执行顺序一步一行，并注明步骤编号是 Trellis 的 id 而非先后序号（原生 1.1–1.4 与新增 1.6/1.7 顺序不一致，所以原来读着混乱） |
| OCR | 先 `ocr llm test`：可用则调用 ocr，否则降级为**委托模式**（agent 自己审并写同格式报告）；不再校验 ocr/git 版本、不再提示安装。按真实 v1.9.8 输出校准：只读 `comments[]`；`summary.comments` 与条数对账；`status: partial` 告警并点名未审文件；全部文件都失败时报错；同一文件同一行的多条 finding 需逐条分诊；报告走 stdout（真实 ocr 没有 `--output`） |
| 门禁开关 | `profile` + `gates.*`，`gate gates`，`doctor` 校验配置；非法配置一律 exit 2 |
| 去重 | 正式 `test --run` 只在 2.4 做一次；implement/check 子 agent 与 pre-commit 只做静态检查；1.7 不再手工重跑 lint-plan |
| design 章节顺序 | **5 数据库变更** 在前，**6 详细设计** 在后（参考评审习惯：先看库表影响再看实现细节） |
| 默认 profile | `strict` → **`standard`** |
| tier 定级流程 | AI 先根据代码给出 S/M/L 建议与理由 → 用户在对话中选择 → 再执行 `gate tier … --reason "…；用户选 X"` |

## 4.1 发现并修复的问题

1. 之前一版的 OCR 调用带 `--output`，而真实 ocr 没有这个参数，会直接失败（依据 `ocr review --help`）。已改为捕获 stdout。
2. 同文件同一行有两条 finding 时，一条分诊记录会同时“盖住”两条，造成漏分诊。已改为一对一。
3. 解析第二张需求表时，其表头会被当成“没有编号的需求”。已改为读取所有表。
4. 全部文件审查失败时 `comments` 为空，会被当成“无问题”。已改为报错。

## 5. 取舍与偏离（请知悉）

- `task.py start` 仍会复查计划类门禁（align / lint-plan / design-review），没有按先前口头方案去掉：去掉会放过 lint-plan 之后再改过的文档。想更省事用 `profile: light` 或单项 `off`。
- `profile` 的 standard / light 取值是方案建议值，使用中可用 `gates.*` 覆盖。
- 方法级单测检查（按方法名近似）默认只告警；单测与 Maven 相关优化按你的决定保持现状。
- implement.md 体积上限（20 KB）未调整。

## v2.1 调整

版本号 `2.1.0`；`/grill-me` 改为可选；design「整体方案」只写本次方案；评审与 OCR 先列后改；OCR 过期基准改为分诊，`--force` 须带理由并留审计；澄清阶段覆盖 `trellis-brainstorm` 以减少重复读代码；standard 档关闭 `manifests`，流程不再要求手工 `pre-commit`。细节与取舍见 `docs/HANDOFF.md` §8。
